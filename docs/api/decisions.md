# API contract decision register

The frozen answer for every endpoint the dashboard disagrees with the backend about.
**This file is the tiebreaker.** When the three sources (backend source, Postman collection,
deployed API) conflict, whatever is written here wins, and the plan phases build against it.

- **Last updated:** 2026-08-10 (revised after running `artisan route:list`)
- **Backend reference:** `4th_year_projects_refractored` @ `3eb54ad` (= `origin/main`, 2026-08-09)
- **Evidence:** [`route-list.json`](./route-list.json) — **now authoritative**, generated by `php artisan route:list --json` · [`probe-results.md`](./probe-results.md) (live probe — inconclusive, no reachable backend)

Status values: **RESOLVED** (decided, safe to build) · **PENDING** (needs the backend developer) · **BLOCKED** (work cannot start).

> **Update — Q1–Q5 are now settled by the framework itself.** PHP 8.2 + Composer were installed
> locally and `php artisan route:list --json` ran against the checkout, so the route table is
> Laravel's own, not a parse of the source. **None of the disputed endpoints exist.** What remains
> open is only *intent*: whether the backend developer plans to add them. Build against the
> fallbacks; they are no longer guesses.

## B. Resolved from the backend source (safe to build on now)

These needed no probe; reading `routes/api.php`, the controllers and the middleware settles them.

| # | Item | Decision | Evidence |
|---|---|---|---|
| B1 | Auth token model | `/admin/login` and `/staff/login` both issue **`StaffJwtService` tokens** — interchangeable. The `auth_kind` refresh split is redundant but harmless | `AdminAuthService::authenticate()` delegates to `StaffJwtService::generateTokenPair()` |
| B2 | `/admin/login` eligibility | **`system_admin` and `sycash` only** (`role->isAdminRole()`). Accepts `username` **or** `email` in the `email`/`username` field | `AdminAuthService::authenticate()` |
| B3 | Legacy user-JWT fallback | **Removed.** `staff` middleware decodes staff tokens only; no on-the-fly Employee creation | `StaffJwtMiddleware` class docblock, "OLD → … NEW → single path" |
| B4 | Role source of truth | `GET /staff/me`. The dashboard must **stop** hardcoding `role: 'system_admin'` on the `/admin/login` path | `authApi.ts:66` vs `StaffAuthController::me()` |
| B5 | New role | **`sycash`** exists (level 3, Financial Administrator, `isRestricted()` → cannot be created or deleted via API) | `app/Enums/StaffRole.php` |
| B6 | Creatable roles for a `system_admin` | **`admin` and `support_agent` only** — the store validator builds its `in:` rule from `creatableRoles()` | `EmployeeManagementController::store()` |
| B7 | `system_admin` route reach | **All 66 guarded** `/admin/*`, `/staff/*` and `/employees/*` routes, plus the 4 public auth routes (`admin/staff` × `login/refresh`). The other 58 routes are `jwt`-guarded end-user APIs (rides, chat, bookings) and are **not** callable with a staff token. Confirmed per-route in `route-list.json` (`system_admin_can_call`) | `route-list.json` (143 routes total: 19 public, 58 end-user, 66 staff-guarded) |
| B8 | Complaint filter values | `index` accepts `status` ∈ `pending, in_review, resolved, closed` — **`escalated` is NOT valid there** and will 422. Escalated complaints live at `GET /staff/escalated-complaints` | `StaffComplaintController::index()` validator |
| B9 | `GET /staff/complaints/{id}` side effect | Opening a **pending** complaint transitions it to `in_review` and assigns it to the caller. The UI must reflect this, not treat it as a read | `StaffComplaintController::show()` → `openComplaint()` |
| B10 | `/staff/complaints/metrics` collision | Even if added later, it **must** be registered before the `{id}` route. As of `3eb54ad` the dashboard's call resolves to `show(0)` | `routes/api.php:355-356` |
| B11 | Review/complaint `date` filter | Exactly two values: `last_7_days`, `last_30_days`. Anything else 422s | both `index()` validators |
| B12 | Users `date` filter | Five values: `all, last_30_days, last_3_months, last_6_months, last_12_months` — different vocabulary from B11 | `AdminUserController::index()` |
| B13 | Ban payload | `reason` (≥10 chars), `type` ∈ `permanent\|temporary`, `expires_at` required when temporary | `AdminBanController` + Postman bodies |
| B14 | Pagination caps | `per_page` max **50** on complaints/reviews/trips/users; trips default 15, users default 10 | the four `index()` validators |
| B15 | Server-side caching | `/admin/dashboard` and `/dashboard/stats` cached **5 min**, `/growth` 15 min, `/cities` 30 min, `/recent` 60 s. A refresh button will not always show new data — say so in the UI | `AdminDashboardController` `Cache::remember` TTLs |
| B16 | Deployment target | `docker compose up` → nginx **:8080** → 3× Octane/RoadRunner. Matches the newest Postman `base_url` | `docker-compose.yml`, collection variable |
